# Critique Report: Runtime Foundation

**Date**: 2026-09-11

**Feature**: [spec.md](../spec.md)

**Plan**: [plan.md](../plan.md)

**Verdict**: PROCEED WITH UPDATES

## Executive Summary

The slice preserves the released CLI and establishes configuration behavior without
shipping placeholder product surfaces. Seven issues need correction before task
generation. Five are blocking because the artifacts disagree about scope, validation
order, path identity, architecture authority, or acceptance infrastructure.

## Product Lens Findings

| ID | Severity | Category | Finding | Suggested change |
|---|---|---|---|---|
| P1 | Must address | Scope | User Story 1 describes an upgrade, but spec 016 owns installation and upgrades. | Describe a user running a source build after the runtime reorganization. |
| P2 | Recommendation | Success measurement | The 10 ms target and 100-key scale have no measured baseline or user outcome. | Require a recorded baseline and no statistically significant regression; set a threshold only from evidence. |

## Engineering Lens Findings

| ID | Severity | Category | Finding | Suggested change |
|---|---|---|---|---|
| E1 | Must address | Compatibility | The browser scenario adds Chromium, while 0.0.2 detects only Firefox and Google Chrome. | Preserve exactly the two released browser rows in spec 005. Leave broader discovery to spec 011. |
| E2 | Must address | Security | The data-model flow parses project configuration before it validates project-root containment. This contradicts the acceptance criterion that rejects the path without reading it. | Validate path identity and containment before opening the project file. |
| E3 | Must address | Architecture | Root identity does not define Windows case handling, existing-file identity, or protection against a link changing during a read. | Define platform-aware identity and a pre-read plus post-read metadata check. State the same-user race assumption. |
| E4 | Must address | Architecture | Spec 001's plan names five final crates, while this plan introduces `matinee-runtime` and implies six. | State that the more specific 005 plan supersedes only the non-normative repository layout in 001. Keep 001's product contracts authoritative. |
| E5 | Must address | Acceptance | SC-005-003 requires macOS, Linux, and Windows evidence, but Stage 4 does not add a CI matrix or equivalent cross-platform gate. | Add the three-platform CI matrix and a Rust 1.85 job to the implementation sequence. |
| E6 | Recommendation | Dependency risk | `directories` 6.0.0 does not declare an MSRV in its packaged manifest. | Require a Rust 1.85 dependency build before accepting the dependency. |
